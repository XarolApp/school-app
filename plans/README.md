## Recommended order

**001 first, and separately from the others.** It is the actual cause of the reported
"text is not visible" symptom, it is a five-line change to a dev-only file, and until
it is fixed the preview harness misreports what every other change looks like. Fixing
it first means 002 can be verified through a preview that is telling the truth.

**002 second.** Independent of 001 in code terms (different files, no shared symbols),
but much easier to judge visually once 001 is done.

**003 any time.** Fully independent of both. Cosmetic and desktop-only.

No plan blocks any other at the code level; the ordering is about verification quality.

## Root causes, briefly

- **001** — `.phone` is 390px wide *including* 14px of bezel padding, so its inner
  window is 362px, but the iframe inside it is hard-coded to 390px with
  `overflow: hidden` on the container. 28px of the app's right edge and 28px of its
  bottom are clipped. **This bug is in the preview harness, not the onboarding.** The
  app itself measured clean at 390×844, 375×667, 360×560 and 320×480.
- **002** — the paywall's sticky bottom container holds four blocks (two buttons, a
  four-line trust list, a mock-payment note) totalling a fixed 317px. That is 38% of
  an iPhone 14 viewport and 57% of a 360×560 Android viewport. The
  `linear-gradient(… 78%, transparent)` on it lets content show through as it scrolls
  underneath, which is what read as a broken scroll animation. Every other screen's
  sticky bar is 11–19%.
- **003** — the `@media (min-width: 640px)` block was not updated during the
  2026-08-24 design-system port, so `.ob-title` shrinks from 32px to 30px as the
  viewport widens.

## Considered and rejected

- **"The onboarding layout is broken on mobile."** Measured and rejected. Zero
  horizontally-overflowing elements and zero top-clipped elements across four
  viewports down to 320×480. The reported symptom traces entirely to 001.
- **"The paywall has a broken scroll animation."** Rejected as stated — there is no
  scroll animation on the paywall. The real defect is sticky-element height (002); the
  gradient overlay makes it *look* like an animation artefact.
- **Adding a test framework** to make these verifiable automatically. Out of scope for
  a bug-fix run and a standing architectural decision the maintainer should make
  deliberately. All three plans use browser assertions instead.
